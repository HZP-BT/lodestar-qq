# ADR 0001：后端范围——不提供官方 QQ Bot API 适配器

- 状态：Accepted
- 日期：2026-11-11
- 决策者：项目所有者、维护者

## 背景

Lodestar 的立项动机是解决两类真实问题：

1. NapCat 无头版频繁掉线、账号被封；
2. SnowLuma 的静默假死、QQ 升级后注入失效。

也就是说，本项目的目标路线是 **“附着真实 NTQQ 客户端 + 工程化保活”**，而不是寻找一个“更合规但能力受限”的替代通道。

## 决策

Lodestar 的后端只有两类：

1. **外部 OneBot 后端**（NapCat / SnowLuma / LLOneBot 等，M1 起）；
2. **原生 NTQQ 注入适配器**（M3 spike，可选）。

**不提供官方 QQ Bot API 适配器，也不为它保留 Adapter 插槽或占位接口。**

## 被否决的备选方案

### 官方 QQ Bot API 作为默认/一等适配器

否决理由：

- 官方群机器人在消息类型、主动推送能力、接入资质上有限制，无法承载“真实客户端全量消息 + 主动推送 + 群管理”的目标。
- 把它做成“合规退路”只是自我安慰：它不能替代注入路线要解决的问题，反而会稀释架构重心。
- 保留一个永远不会成为主路径的 Adapter 插槽，会让接口、文档和测试长期背负无效分支。

## 后果

- 架构、文档、测试只围绕“外部 OneBot 后端 + 原生注入适配器”两类后端。
- README 必须写实风险：注入路线属第三方方案，只能降低、不能归零账号风险；风险由使用者自担。
- 合规性由使用方式兜底：最小频控、行为正常化、群白名单、@ 触发、每日额度、一键停用；不再由后端类型兜底。
- 非目标同步收紧：不做批量注册养号、群发营销、加好友引流、绕过验证码与安全验证的对抗手段。

## 重新审议的触发条件

满足以下任一条件时，可以重新讨论是否引入官方 Bot API 适配器：

1. 官方 Bot API 向个人账号开放群聊，并支持本项目需要的主要消息类型与主动推送能力；
2. 项目范围从“个人/小规模自用”转为需要官方合规通道的商业产品；
3. 监管或平台政策要求必须使用官方接口，且注入路线不再可用。

在此之前，不新增 `adapter-official` 包、不保留相关接口占位。
